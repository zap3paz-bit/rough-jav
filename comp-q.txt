1.Why is comparing only adjacent elements sufficient?
In bubble sort, adjacent elements are repeatedly compared and swapped if they are in the wrong order. 
Each swap moves a larger element one position toward the right. 
By repeating these comparisons, an element can move through many positions in a single pass.
For example, in 4 3 2 1, the 4 moves step-by-step: 4→3, 4→2, 4→1, eventually reaching the end.

2.Loop Invariant:inner loop->
After each complete pass of the inner loop, the largest element in the unsorted portion is placed at its correct position at the end.
a. Initialization:Before the first pass, no elements have been sorted yet. Therefore, the invariant is initially true.
b. Maintenance:During each pass, adjacent elements are compared and swapped when they are in the wrong order. 
Thus, the largest element in the unsorted portion moves toward the end. At the end of the pass, it reaches its correct position.
c. Termination:When all passes are completed, every element has been placed in its correct position. Therefore, the entire array is sorted.
d. Correctness:Since the invariant is maintained after every pass and each pass places one largest unsorted element in its final position, 
after all passes the array must be sorted.

outer loop:
Loop Invariant: After each iteration of the outer loop, the last i elements are sorted and are in their final correct positions.
Initialization: Initially, no elements are sorted, so the invariant holds.
Maintenance: Each pass places the largest element of the unsorted portion at its correct position at the end.
Termination: When all passes are completed, all elements are in their correct positions.
Correctness: Hence, the array is sorted correctly.

3.Why does the largest unsorted element “bubble” toward the end?
The inner loop always compares the current element to its right neighbor and swaps if the current one is larger.
This means whichever element is largest so far gets carried forward and swapped repeatedly until it hits a bigger one or reaches the end

4.How does optimized bubble sort recognize an already sorted array?
It uses a swap flag (for example, swapped).Initially, swapped = false.Whenever two elements are swapped, set swapped = true.
After a complete pass, if swapped is still false, no swaps occurred.Therefore, the array is already sorted, and the algorithm stops.

5.. Why does early termination make bubble sort adaptive?

An algorithm is adaptive if its running time changes according to how sorted the input already is.
In optimized bubble sort, if the array is already sorted or nearly sorted, very few swaps are needed. The algorithm detects a pass with no swaps and stops early.
The basic version always performs all its passes, even when the array is already sorted.
Therefore:
Basic bubble sort: does not take advantage of existing order.
Optimized bubble sort: performs fewer comparisons/passes when the array is already or nearly sorted.

An online algorithm must produce useful sorted output while input is arriving and should update the result as new elements are received. 7. Answer

Both exploit existing order, but differently. Bubble sort exploits order mainly by detecting passes with no swaps and stopping early. Insertion sort directly uses the existing sorted prefix: if the next element is already in the correct position, it performs little or no movement. Thus insertion sort more directly adapts to local order.

8. Answer

Bubble sort moves elements through a sequence of adjacent swaps. Even when only a small final rearrangement is needed, an element may have to cross many positions one at a time. Each crossing can require a separate swap, causing many swaps.

9. Answer

A very small element near the end moves left only one position per pass in a standard left-to-right bubble sort. A very large element near the beginning can move rapidly to the right during the same pass because it wins each adjacent comparison. Thus the scan direction makes large elements move quickly right while small elements move slowly left.

10. Answer

The swaps reveal how many adjacent inversions or local disorder exists. Each adjacent swap removes an inversion, so the total number of swaps in ordinary bubble sort is related to the number of inversions in the input. More disorder generally means more swaps.

11. Answer

An implementation that minimizes unnecessary swaps, or another algorithm with fewer writes, may be preferable.

12. Answer

Bubble sort is stable when it swaps only when the left key is strictly greater than the right key. Equal elements are therefore never exchanged, so their original relative order is preserved. If equal elements are also swapped, their relative order may change and stability can be lost.

18. Answer

Selection sort's outer-loop invariant is that the sorted prefix contains the smallest elements in their final positions. During the inner loop, the algorithm maintains an index pointing to the smallest element found so far in the remaining unsorted portion. Bubble sort instead progressively places the largest remaining element at the end through adjacent swaps.

26. Answer

27. Answer

28. Answer

29. Answer

Shifting elements instead of swapping can preserve stability if done carefully: after finding the minimum, elements between its current position and the target position are shifted right, and the minimum is inserted into the gap. This reduces the risk of changing the relative order of equal keys, but it can increase the number of movements.

30. Answer

31. Answer

32. Answer

33. Answer

35. Answer

62. Answer
